Network Technology — จับคู่ข้อสอบ 2565 กับ 2568 แล้วสอนเนื้อหาที่ออกจริง

อ่านข้อสอบทั้งสองชุดแล้วพบว่าโครงสร้างซ้ำกันมาก แค่ตัวเลขกับมุมคำถามเปลี่ยน — เอกสารนี้สอนเนื้อหาแต่ละเรื่องพร้อมเหตุผล ไม่ใช่แค่คำตอบ แล้วให้ฝึกทำโจทย์แบบเดียวกับที่จะเจอในห้องสอบ

กลยุทธ์ อาจารย์ออกข้อสอบซ้ำโครงสร้างเดิมแต่ "พลิกแผลง" ตัวเลข/ทิศทางคำถาม — เช่น ปี 65 ถามหาโมดูเลชันที่ ผิดพลาดน้อยที่สุด ปี 68 อาจถามหาโมดูเลชันที่ ผิดพลาดมากที่สุด จากกราฟเดียวกัน ดังนั้นสิ่งที่ต้องแม่นคือ วิธีอ่านกราฟ/ตาราง ไม่ใช่จำคำตอบตัวเดียว — ทุกหัวข้อด้านล่างจึงเน้นสอน "อ่านยังไง" ก่อน แล้วค่อยฝึกในทั้งสองทิศทาง
01

Physical Layer — BER, Modulation, และปัจจัยเรื่อง Data Rate

ออกทั้ง 2 ปี · น้ำหนักคะแนนสูงสุดของข้อสอบ (CLO1)

แนวคิดหลัก: Bit Error Rate (BER) คืออะไร

BER คือสัดส่วนของบิตที่ส่งออกไปแล้ว "ผิดพลาด" เมื่อไปถึงปลายทาง เทียบกับจำนวนบิตทั้งหมดที่ส่ง เป็นตัวชี้วัดคุณภาพที่ระดับ Physical Layer โดยตรง ยิ่ง BER ต่ำ = สัญญาณยิ่งน่าเชื่อถือ

ปัจจัยที่ทำให้ข้อมูลผิดพลาดที่ระดับ Physical Layer (สำหรับข้อ 1.1)

  • Attenuation (การลดทอนสัญญาณ) — สัญญาณอ่อนกำลังลงเรื่อย ๆ ตามระยะทางที่เดินทาง ยิ่งไกลยิ่งอ่อน จนเครื่องรับแยกแยะ 0/1 ผิดพลาด
  • Noise / Interference (สัญญาณรบกวน) — สัญญาณจากภายนอก (thermal noise, crosstalk, คลื่นแม่เหล็กไฟฟ้า) มาปะปนกับสัญญาณจริง ทำให้ค่าที่วัดได้คลาดเคลื่อน

ปัจจัยรองอื่น ๆ ที่อาจใช้เสริมได้ถ้าโจทย์ขอมากกว่า 2 ข้อ: Delay distortion (ความถี่ต่างกันเดินทางเร็วช้าไม่เท่ากัน) และ Bandwidth ของช่องสัญญาณ

ทำไมข้อนี้จึงตอบแค่ "Noise" เฉย ๆ ไม่ได้เต็มคะแนน
โจทย์ให้คะแนนตามการอธิบายว่าปัจจัยนั้นทำให้เกิด error ได้อย่างไร ไม่ใช่แค่เอ่ยชื่อ ต้องเขียนกลไก เช่น "ระยะทางไกลทำให้พลังงานสัญญาณลดลง เมื่อถึงตัวรับสัญญาณอ่อนจนต่ำกว่า threshold ที่แยก 0/1 ได้ชัดเจน จึงตีความผิด"

อ่านกราฟ BER vs Eb/N0 ให้เป็น (ข้อ 1.2 — จุดที่ "พลิกแผลง" บ่อยที่สุด)

แกน X = Eb/N0 (dB) หมายถึงพลังงานสัญญาณเทียบกับสัญญาณรบกวน ยิ่งมากยิ่งดี  |  แกน Y = log10(Probability of Error) ยิ่งต่ำ(ลบมาก)ยิ่งดี

หลักอ่านกราฟ: ที่ Eb/N0 เท่ากัน เส้นที่อยู่ ซ้าย/ล่างกว่า = ผิดพลาดน้อยกว่า = โมดูเลชันนั้น "ดีกว่า" หรือ "ทนทานกว่า"  |  เส้นที่อยู่ ขวา/บนกว่า = ต้องใช้พลังงานสูงกว่ามากถึงจะ error ต่ำเท่ากัน = "แย่กว่า"/เสี่ยง error มากกว่า

1.2.1 — ผิดพลาดน้อยที่สุด: BPSK / QPSK / 4-QAM (เส้นซ้ายสุด อยู่ต่ำสุดตลอดช่วง Eb/N0)

ถ้าโจทย์พลิกถามหา "มากที่สุด" แทน (แนวโน้มที่จะเจอในข้อสอบจริงของคุณ): คำตอบคือ 32-PSK (เส้นขวาสุด ต้องใช้ Eb/N0 สูงที่สุดกว่าจะได้ error ต่ำเท่าเส้นอื่น)

1.2.2 — ถ้าสัญญาณรบกวนต่ำมาก (สภาพแวดล้อมดี): เลือกโมดูเลชันแบบ order สูง เช่น 32-PSK/64-QAM ได้ เพราะแม้จะ error ง่ายกว่าในสภาพแวดล้อมแย่ แต่ตอนนี้ noise ต่ำจึงไม่ค่อย error อยู่แล้ว และโมดูเลชัน order สูงส่งข้อมูลได้เร็วกว่า (บิต/สัญลักษณ์มากกว่า) — กลับกัน ถ้าโจทย์บอกว่าสัญญาณรบกวนสูงมาก ต้องเลือกตัวที่ทนทานที่สุดคือ BPSK/QPSK

1.2.3 — ต้องการ Error < 10⁻⁴ เมื่อ Eb/N0 ต่างกัน 10 เท่า: แปลงอัตราส่วน 10 เท่าเป็น dB ก่อน: 10·log10(10) = 10 dB จากนั้นดูที่แกน X = 10 dB ว่าเส้นไหนอยู่ต่ำกว่า −4 แล้วบ้าง แล้วเลือกเส้นที่ order สูงที่สุดในบรรดาเส้นที่ยังผ่านเกณฑ์ (จะได้ throughput สูงสุดโดยยังพอ error ตามเกณฑ์)

กับดัก: ข้อ 1.2.3 ต้องแปลง "ต่างกัน N เท่า" → dB ด้วยสูตร 10·log10(N) ก่อนเสมอ นักศึกษาหลายคนลืมแปลงแล้วเอา N ไปมองบนแกน X ตรง ๆ ซึ่งผิด เพราะแกนเป็น dB ไม่ใช่อัตราส่วนตรง ๆ

ทำไม Standard รุ่นใหม่ (802.11ac / WiFi 7) เร็วกว่ารุ่นเก่าเสมอ

ข้อสอบทั้ง 2 ปีถามแบบเดียวกัน แค่เปลี่ยนคู่เทคโนโลยี (802.11n→ac หรือ WiFi6→7) หลักการตอบเหมือนกันทุกครั้ง มี 3 ปัจจัยหลักที่ผลักดัน data rate ให้สูงขึ้น:

ปัจจัยผลต่อ Data Rate
Channel Bandwidth กว้างขึ้นตาม Shannon/Nyquist ยิ่งแบนด์วิดท์ (Hz) มาก ยิ่งส่งข้อมูล (bit/s) ได้มากขึ้นโดยตรง
Modulation order สูงขึ้น (เช่น 64-QAM → 256-QAM → 1024/4096-QAM)ส่งได้หลาย bit ต่อ 1 สัญลักษณ์มากขึ้น (256-QAM = 8 bit/symbol) ทำให้ throughput สูงขึ้นแม้ bandwidth เท่าเดิม

02

ARP Table และ ARP Poisoning / Spoofing

ออกทั้ง 2 ปี (ข้อ 2) · เชื่อมกับพื้นฐาน SOC ของคุณโดยตรง

หลักคิด: ARP table เก็บอะไร และอัปเดตเมื่อไหร่

ARP (Address Resolution Protocol) แปล IP Address → MAC Address เฉพาะภายใน broadcast domain / subnet เดียวกัน เท่านั้น เครื่องจะสร้างรายการใน ARP cache ก็ต่อเมื่อ เคยส่งข้อมูลหา IP นั้นโดยตรงในเลเยอร์ 2

กฎที่ใช้ตอบข้อ ARP table ได้ทุกข้อ: ถ้าปลายทางอยู่คนละ subnet เครื่องต้นทางจะไม่มี ARP entry ของปลายทางจริง แต่จะมี entry ของ Default Gateway (Router) แทน เพราะเฟรม L2 ถูกส่งไปหา Router ก่อนเสมอ ไม่ได้ส่งตรงถึงปลายทางข้าม subnet

ตัวอย่างจากข้อสอบปี 65 (Host A, B ใน 10.0.0.0/24 ・ Host D ใน 10.0.4.0/24 ผ่าน Router)

เฉลย ARP table ของ Host A, B, D

Host A (10.0.0.11) — อยู่ subnet เดียวกับ B และ Router interface ฝั่งซ้าย: มี entry ของ Host B (10.0.0.22 → 0053.ffff.bbbb) และ Router (10.0.0.99 → 0053.ffff.9999) — ไม่มี entry ของ Host D โดยตรง เพราะ D อยู่คนละ subnet

Host B (10.0.0.22) — เช่นเดียวกับ A: มี entry ของ Host A (10.0.0.11 → 0053.ffff.aaaa) และ Router (10.0.0.99 → 0053.ffff.9999)

Host D (10.0.4.44) — อยู่คนละ subnet กับ A/B มองเห็นแค่ Router ฝั่งขวา: มี entry ของ Router (10.0.4.99 → 0053.ff44.9999) เท่านั้น เวลาส่งหา A หรือ B ก็ส่งผ่าน MAC ของ Router ตัวนี้เสมอ

ARP Poisoning / Spoofing คืออะไร และทำไมมันทำได้

ช่องโหว่รากฐาน: โพรโทคอล ARP ไม่มีการยืนยันตัวตน (no authentication) เครื่องไหนก็ตามสามารถส่ง ARP Reply ออกไปได้แม้ไม่มีใครถาม (Gratuitous ARP) และเครื่องที่ได้รับจะเชื่อและอัปเดต cache ทันทีโดยไม่ตรวจสอบว่าคำตอบนั้นมาจากเจ้าของ IP จริงหรือไม่

ขั้นตอนการโจมตี (รูปแบบมาตรฐานที่ใช้ตอบได้ทุกโจทย์ ARP poisoning)

  • Attacker ส่ง ARP Reply ปลอมไปยัง Host เป้าหมาย โดยอ้างว่า "IP ของเป้าหมายจริง (เช่น Router หรือ Host อื่น) ตอนนี้ผูกกับ MAC ของ Attacker"
  • Host เป้าหมายไม่ตรวจสอบ เชื่อทันทีและเขียนทับ (overwrite) entry เดิมใน ARP cache ด้วย MAC ของ Attacker
  • ทุกเฟรมที่ Host ตั้งใจส่งหา IP นั้น จะถูกส่งไปที่ MAC ของ Attacker แทน — Attacker ดักอ่าน/แก้ไข แล้วอาจ forward ต่อให้ปลายทางจริง (Man-in-the-Middle) เพื่อไม่ให้เหยื่อรู้ตัว
เฉลย 2.2 — Redirect เส้นทางจาก A→D ไปยัง Host C (ตัวอย่างเจาะจงจากข้อสอบ)
จุดสำคัญ: A ส่งข้อมูลหา D (คนละ subnet) โดยส่งเฟรมไปที่ MAC ของ Router เสมอ (ไม่ใช่ MAC ของ D) ดังนั้นการ redirect ที่ได้ผลคือต้อง poison entry ของ Router ใน ARP table ของ Host A ไม่ใช่ poison entry ของ D โดยตรง

วิธีทำ: Attacker (Host C) ส่ง ARP Reply ปลอมไปหา Host A บอกว่า "IP 10.0.0.99 (Router) ตอนนี้อยู่ที่ MAC 0053.ffff.cccc" Host A จะอัปเดต ARP table แล้วส่งทุกเฟรมที่ตั้งใจไปหา Router (รวมถึงที่จะ forward ต่อไป D) มาที่ Host C แทน — C จึงกลายเป็นคนกลางในเส้นทาง A → D

ทดสอบความเข้าใจเร็ว ๆ

Host A อยู่ 192.168.1.0/24 ต้องการส่งข้อมูลหา Server ที่อยู่ subnet อื่นผ่าน Internet ARP table ของ A จะมี entry ของอะไรบ้างที่เกี่ยวกับการส่งครั้งนี้?

Data Link Layer: หน้าที่ และ Error Detection

ออกทั้ง 2 ปี

หน้าที่ของ Data Link Layer (Layer 2)

เก็บเป็น 4 หน้าที่หลักเวลาตอบ จะครบและตรงกับที่ Kurose/Netacad สอน:

  • Framing — ห่อหุ้มข้อมูลจาก Network Layer เป็น "เฟรม" ที่มีขอบเขตชัดเจน (header/trailer) สำหรับส่งบน physical medium
  • Physical Addressing (MAC Addressing) — ระบุต้นทาง/ปลายทางด้วย MAC Address ในเครือข่ายเดียวกัน (LAN)
  • Error Detection (บางกรณี Correction) — ตรวจสอบว่าข้อมูลเสียหายระหว่างทางหรือไม่ (parity, CRC/FCS)
  • Media Access Control — ควบคุมว่าใครมีสิทธิ์ส่งข้อมูลบน medium ที่ใช้ร่วมกัน เพื่อลด/จัดการการชนกัน (collision)

Parity Bit vs CRC/FCS — ต่างกันตรงไหน

Parity BitCRC / FCS
วิธีการนับจำนวนบิต 1 แล้วเติม 1 บิตให้ครบคู่/คี่หารข้อมูลด้วย generator polynomial แล้วเอาเศษมาแนบท้าย
ขนาด check bits1 บิต16 หรือ 32 บิต (ยาวกว่ามาก)
ความสามารถตรวจจับตรวจได้เฉพาะจำนวนบิตผิดที่เป็นเลขคี่ พลาดถ้าผิดพร้อมกันเป็นจำนวนคู่ตรวจจับ burst error และ error pattern ได้ครอบคลุมกว่ามาก แทบทุกกรณีที่พบจริง
แก้ไขข้อผิดพลาดแก้ไม่ได้ (detect only)แก้ไม่ได้เช่นกัน (detect only) — ถ้าต้องการแก้ต้องใช้ ARQ ให้ส่งซ้ำ

Multi-dimensional (2D) Parity — จุดที่ข้อสอบมักดักคำตอบผิด

วิธีนี้จัด data bits เป็นตาราง (แถว×คอลัมน์) แล้วคำนวณ parity ทั้งตามแถวและตามคอลัมน์

กับดักสำคัญ (นักศึกษาในตัวอย่างข้อสอบตอบผิดจุดนี้): คำตอบที่ว่า "ตรวจจับได้อย่างเดียว แก้ไม่ได้" นั้นถูกแค่ครึ่งเดียว — ตามตำรา Kurose บทที่ 5 (Multi-dimensional Parity) การจัดเรียงแบบ 2 มิตินี้สามารถแก้ไข (correct) ข้อผิดพลาดแบบ single-bit error ได้ด้วย เพราะตำแหน่งที่ parity แถวและ parity คอลัมน์ "ผิดพร้อมกัน" จะชี้จุดตัดที่แน่นอนว่าบิตไหนคือบิตที่ผิด ทำให้กลับบิตนั้นให้ถูกต้องได้ทันที (ไม่ต้องขอส่งใหม่)

ข้อจำกัด: วิธีนี้แก้ไขได้เฉพาะกรณี error 1 บิต เท่านั้น ถ้ามีมากกว่า 1 บิตผิดพร้อมกันในตำแหน่งที่ทำให้ parity แถว/คอลัมน์ยังออกมาถูกต้องพอดี (เช่นผิด 4 บิตเป็นรูปสี่เหลี่ยมที่มุมตาราง) ก็จะตรวจไม่พบเลย

วิธีเขียนตอบให้ได้คะแนนเต็มข้อนี้
โครงคำตอบที่ควรมี: (1) บอกว่า detect ได้ด้วย parity แถว+คอลัมน์ (2) บอกว่า correct ได้สำหรับ single-bit error โดยอธิบายกลไก "หาจุดตัดแถว-คอลัมน์ที่ parity ผิด" (3) บอกข้อจำกัดว่า multi-bit error บางรูปแบบตรวจไม่พบ

Medium Access Control Protocol ทำหน้าที่อะไร

ควบคุมว่า ใครมีสิทธิ์ส่งข้อมูลบน medium ที่ใช้ร่วมกัน (shared medium) เมื่อไหร่ เพื่อจัดระเบียบการเข้าถึงและลดหรือจัดการการชนกันของสัญญาณ (collision) เมื่อหลายอุปกรณ์ต้องการส่งพร้อมกัน เช่น CSMA/CD ใน Ethernet แบบเก่า, CSMA/CA ใน WiFi

FDM vs TDM

FDMTDM
วิธีแบ่งแบ่งตามความถี่แบ่งตามช่วงเวลา
ข้อดีส่งพร้อมกันได้ตลอดเวลา ไม่ต้อง sync เวลาใช้ full bandwidth ในช่วงเวลาของตน ไม่ต้องเผื่อ guard band
ข้อเสียต้องมี guard band กันคลื่นรบกวนกัน เสียแบนด์วิดท์ไปเปล่า ๆต้อง sync เวลาแม่นยำ ถ้าไม่มีข้อมูลส่ง ช่วงเวลานั้นก็ยังถูกจองไว้เฉย ๆ (สูญเปล่า)

ทำไม Slot Time ของ Exponential Back-off ใน CSMA/CD ต้องเท่ากับ 512 bit time

ตัวเลข 512 bit time ไม่ได้สุ่มมา แต่มาจากการออกแบบให้เชื่อมโยงกับขนาดเฟรมขั้นต่ำของ Ethernet (minimum frame size = 64 byte = 512 bit) โดยตั้งใจให้:

  • 512 bit time ถูกกำหนดให้เท่ากับเวลาที่สัญญาณใช้เดินทางไป-กลับ (round-trip propagation delay) ในระยะไกลที่สุดที่เครือข่ายรองรับได้ (worst-case)
  • นั่นแปลว่าถ้าสถานีส่งเฟรมขนาดขั้นต่ำ (512 bit) จบไปแล้วโดยยังไม่เจอ collision สถานีนั้นมั่นใจได้ว่าจะไม่มี collision เกิดขึ้นสำหรับเฟรมนี้อีกแล้ว เพราะสัญญาณชนที่อาจเกิดขึ้นจากปลายไกลสุดของเครือข่ายจะเดินทางกลับมาถึงภายในเวลานี้เสมอ
สรุปเป็นประโยคเดียวเพื่อจำเข้าห้องสอบ: Slot time 512 bit = เวลา round-trip ที่แย่ที่สุดของเครือข่าย ถูกผูกกับขนาดเฟรมขั้นต่ำ เพื่อรับประกันว่าการชนกันจะถูกตรวจจับได้เสมอก่อนที่สถานีจะส่งเฟรมจบ — เป็นกลไกที่ทำให้ CSMA/CD "detect" การชนได้อย่างน่าเชื่อถือ ซึ่งเป็นฐานของการคำนวณเวลารอ (back-off) ที่ตามมาด้วย

IP Addressing & VLSM Subnetting

CLO 2 — คะแนนเดี่ยวก้อนใหญ่ที่สุดรองจาก Physical Layer ต้องทำได้ 100%

ขั้นตอนคิดที่ใช้ได้กับทุกโจทย์ subnetting แบบนี้ (VLSM)

  1. หาว่า address block เดิมรองรับ host ได้กี่เครื่อง: 2^(host bits) − 2 (ลบ 2 เพราะกัน network address กับ broadcast address ไว้)
  2. เรียงแผนกจากต้องการ host มากไปน้อย แล้วจัดสรรจากบล็อกใหญ่ก่อนเสมอ (หลัก VLSM)
  3. สำหรับแต่ละแผนก หา host bits ที่น้อยที่สุดที่ยังพอ: หา n ที่เล็กที่สุดซึ่ง 2^n − 2 ≥ จำนวนคนที่ต้องการ
  4. subnet mask = 32 − n (bit) แปลงเป็น dotted decimal
  5. Network address = จุดเริ่มของบล็อกนั้น, Broadcast = จุดสุดท้ายของบล็อกนั้น, Host range = ระหว่างกลาง (ไม่รวมหัวท้าย)
  6. บล็อกถัดไปเริ่มต่อจาก broadcast address ของบล็อกก่อนหน้า +1 เสมอ
กับดักคำนวณจำนวน host bits: อย่าใช้ log2(จำนวนคน) ตรง ๆ เพราะลืมหัก 2 (network+broadcast) ให้เช็คด้วยการลองแทนค่าเทียบเสมอ เช่น 50 คน → n=6 ให้ 2⁶−2=62 ≥ 50 ✓ แต่ n=5 ให้ 2⁵−2=30 < 50 ✗ ดังนั้นต้องใช้ n=6 ไม่ใช่ n=5

ลองคำนวณเอง — Subnet Sizing Calculator

ใส่จำนวนโฮสต์ที่ต้องการ ระบบจะบอก host bits ที่น้อยที่สุด, prefix, และ subnet mask ที่ต้องใช้ — ใช้ฝึกความไวก่อนเข้าห้องสอบ

โจทย์จริงจากข้อสอบ — ฝึกเต็มรูปแบบ 2 เวอร์ชัน

Routing: อ่านตาราง, Static/Dynamic, Distance Vector/Link State

ออกทั้ง 2 ปี ด้วยรูปแบบใกล้เคียงกันมาก

อ่าน Routing Table ให้เป็น (โจทย์ Cisco `show ip route`)

โค้ดหน้าแต่ละบรรทัด (C, S, R, O, ...) บอกว่า route นั้นมาจากไหน:

CConnected — เชื่อมต่อโดยตรงกับ interface ของ router นี้
S / S*Static — ผู้ดูแลระบบพิมพ์คำสั่งกำหนดเส้นทางเองด้วยมือ (S* มักหมายถึง default route แบบ static)
RRIP — เรียนรู้มาจากโพรโทคอล RIP (administrative distance = 120)
OOSPF — เรียนรู้มาจากโพรโทคอล OSPF
หลักการหา Exit Interface: Router จะเทียบ IP ปลายทางกับทุก route ในตาราง แล้วเลือก route ที่ "แม่นยำที่สุด" (longest prefix match) ถ้าไม่มี route ใดตรงกับปลายทางเลย จะใช้ default route (0.0.0.0/0) เป็นทางเลือกสุดท้ายเสมอ (ถ้ามีอยู่ในตาราง)

192.168.15.227 ไม่ตรงกับ 192.168.10.0/24 และไม่ตรงกับ 192.168.11.0/24 (octet ที่ 3 คือ .15 ต่างจากทั้งคู่) จึงไม่มี route เฉพาะเจาะจงใด ๆ ตรงกันเลย ทำให้ router ตกไปใช้ default route ที่ระบุว่า 0.0.0.0/0 [120/1] via 209.165.200.226 ซึ่งออกทาง Serial0/0/0

Transport Layer — RTT กับ RTO

ข้อสุดท้ายของข้อสอบปี 65 (ยังไม่มีในปี 68 แต่ยังควรเตรียมไว้)

ความสัมพันธ์ RTT กับ RTO ที่ต้องเข้าใจ

RTT (Round-Trip Time) = เวลาจริงที่ข้อมูลใช้เดินทางไป-กลับ  |  RTO (Retransmission Timeout) = เวลาที่ผู้ส่ง "รอ" ก่อนจะตัดสินใจว่า packet หายแล้วส่งใหม่

หลักคิด: เทียบขนาด RTO กับ RTT เสมอ ถ้า RTO ใหญ่กว่า RTT มาก = รอนานเกินจำเป็นเวลาที่มี loss / ถ้า RTO เล็กกว่า RTT = จะเกิด timeout ก่อนที่ ACK จะมีโอกาสกลับมาถึงด้วยซ้ำ

สถานการณ์ผลกระทบต่อประสิทธิภาพ
Loss Rate สูง, RTO=50ms, RTT=1msRTO ใหญ่กว่า RTT ถึง 50 เท่า และ loss เกิดบ่อย → ทุกครั้งที่หาย ผู้ส่งต้องรอนานถึง 50ms (แทนที่จะรู้ตัวใน ~1-2ms) throughput ลดลงมาก เพราะเวลาส่วนใหญ่หมดไปกับการรอเปล่า ๆ
Loss Rate = 0%, RTO=50ms, RTT=1msไม่มี packet หายเลย จึงไม่เคยเกิด timeout ขึ้นจริง ค่า RTO ที่ตั้งไว้สูงแค่ไหนก็ไม่กระทบ ประสิทธิภาพ เพราะกลไกนี้ไม่เคยถูกเรียกใช้ — throughput ถูกจำกัดด้วย RTT/window size ตามปกติเท่านั้น
packet สูญหาย, RTO=2ms, RTT=20msRTO เล็กกว่า RTT! ผิดปกติ/misconfigured — ผู้ส่งจะ timeout และส่งซ้ำก่อนที่ ACK ของรอบแรกจะมีโอกาสเดินทางกลับมาถึงด้วยซ้ำ เกิด spurious retransmission (ส่งซ้ำทั้งที่จริง ๆ อาจไม่ได้หาย) สิ้นเปลือง bandwidth และทำให้ระบบเข้าใจผิดว่าเครือข่ายแออัดกว่าความจริง
กับดักที่พบบ่อย: หลายคนตอบว่า "RTO สูง = แย่เสมอ" แต่จริง ๆ ต้องดูคู่กับ Loss Rate ด้วย ถ้าไม่มี loss เลย ค่า RTO จะไม่ถูกใช้งานเลยและไม่กระทบอะไร — โจทย์แบบนี้ทดสอบว่าเข้าใจว่า "RTO ถูกทริกเกอร์เมื่อไหร่" ไม่ใช่แค่จำว่าตัวเลขไหนดีกว่า
