5 Essential Characteristics

  • On-Demand Self-Service: กดสั่งใช้ได้ทันทีไม่ต้องผ่านคน
  • Broad Network Access: เข้าถึงผ่านเครือข่ายมาตรฐาน
  • Resource Pooling: ใช้ทรัพยากรร่วมกัน (Multi-tenant)
  • Rapid Elasticity: ขยาย/ลด Dynamic รวดเร็ว
  • Measured Service: จ่ายตามจริง (Pay-as-you-go)

3 Service Models

  • IaaS: เช่า Infra (EC2, VPC) ลูกค้าคุม OS, App, Data
  • PaaS: เช่า Platform (Elastic Beanstalk, RDS) คุมเฉพาะ App, Data
  • SaaS: เช่าซอฟต์แวร์สำเร็จรูป (M365, Salesforce) ผู้ใช้ใช้งานอย่างเดียว

4 Deployment Models

  • Public Cloud: คลาวด์สาธารณะ จ่ายตามใช้
  • Private Cloud: ใช้เฉพาะองค์กรเดียว ควบคุมสูงสุด
  • Hybrid Cloud: ผสมระหว่าง Private + Public
  • Community Cloud: ใช้ร่วมในกลุ่มองค์กรที่มีเป้าหมายเดียวกัน

1.4 Shared Responsibility Model Matrix

ขอบเขต (Scope) AWS Responsibility (Security OF the Cloud) Customer Responsibility (Security IN the Cloud)
Physical & Infrastructure ✅ Data Center Security, Hardware, Facilities, Power ❌ ลูกค้าไม่ต้องดูแล
Hardware & Network Infra ✅ Routers, Switches, Storage Disks, Virtualization/Hypervisor ❌ ลูกค้าไม่ต้องดูแล
Guest Operating System (EC2 OS) ❌ AWS ไม่ยุ่งกับ OS ภายในเครื่อง EC2 ✅ การอัปเดต Patch OS, Firewall Configuration ในเครื่อง
IAM & Access Management ✅ ระบบพื้นฐาน IAM ให้พร้อมใช้งาน ✅ การตั้งค่า Users, Groups, MFA, Policies, Least Privilege
Data & Encryption ✅ ให้เครื่องมือ KMS / Server-side Encryption ✅ การเปิดใช้งาน Encryption (Client-side/Server-side), Data Classification

ผลการวิเคราะห์จะแสดงที่นี่หลังจากกดปุ่มตรวจสอบ...

💡 ขั้นตอนการตั้งค่า MFA และเหตุผลที่ต้องกรอกรหัส 2 ชุดติดต่อกัน (ออกสอบบ่อย!)

ขั้นตอนใน Lab 2-1:

  1. เข้า IAM Console → Users → เลือก User (เช่น Administrator)
  2. ไปที่แถบ Security credentials → คลิก Assign MFA device
  3. เลือก Authenticator app (Virtual MFA) → สแกน QR Code ด้วย Google Authenticator
  4. ป้อนรหัส OTP 6 หลักแรกในช่อง MFA code 1
  5. รอ 30 วินาทีให้รหัสเปลี่ยน แล้วป้อนรหัสชุดที่สองในช่อง MFA code 2
  6. กด Add MFA เสร็จสิ้นกระบวนการ
🧠 เหตุผลทางเทคนิค (Why Two Consecutive Codes?)

การป้อนรหัส OTP 2 ชุดติดต่อกัน (ที่ห่างกัน 30 วินาที) มีวัตถุประสงค์เพื่อ **Synchronize เวลา (Time Synchronization)** ระหว่างนาฬิกาของอุปกรณ์สมาร์ตโฟนผู้ใช้กับ AWS MFA Server

⚠️ หากเครื่องผู้ใช้เวลากลมไม่ตรงกับ Server การอ่านรหัส 2 ชุดติดต่อกันช่วยให้ AWS คำนวณ Clock Drift และปรับเวลาให้อยู่ในระยะยอมรับได้

🔢 AWS Subnet IP Reservation Rule (สูตรคำนวณที่ต้องจำ)

ในทุกๆ Subnet AWS จะ **จอง IP ไว้ 5 หมายเลขเสมอ** (3 IP แรก, 1 IP เครือข่าย, และ 1 IP บรอดแคสต์) ไม่สามารถนำไปมอบให้ EC2 ได้

ตัวอย่าง Subnet CIDR Block:
10.0.0.0/24 (Total 256 IPs)
จำนวน IPs ทั้งหมด:256 IPs
หักจองโดย AWS:- 5 IPs
เหลือใช้งานจริง (Available IPs):251 IPs
รายชื่อ 5 IP Addresses ที่ถูก AWS จอง:
1. 10.0.0.0 - Network Address
2. 10.0.0.1 - Reserved by AWS for VPC Router
3. 10.0.0.2 - Reserved for AWS DNS Server
4. 10.0.0.3 - Reserved for Future Use
5. 10.0.0.255 - Network Broadcast Address

3.5 Security Group (SG) vs Network ACL (NACL) Matrix

คุณลักษณะ (Feature) Security Group (SG) Network ACL (NACL)
ระดับการทำงาน (Level) Instance Level (ผูกกับตัว EC2) Subnet Level (ผูกกับทางเข้า-ออก Subnet)
สถานะทราฟฟิก (Statefulness) Stateful (ถ้ารับ Inbound อนุญาต ขาออก Outbound จะอนุญาตอัตโนมัติ) Stateless (ต้องตั้งค่ากฎทั้งขาเข้า Inbound และขาออก Outbound แยกกัน)
กฎการกรอง (Rules) Allow เท่านั้น (ไม่มี Deny) Allow และ Deny (สั่งบล็อก IP เฉพาะเจาะจงได้)
ลำดับการประมวลผล ประมวลผล ทุก Rules ก่อนตัดสินใจ ประมวลผล ตามลำดับเลข Rule Number (น้อยไปมาก) เจอที่ match แล้วหยุดทันที

⚠️ Resource Cleanup Sequence & Cost Optimization (ออกสอบบ่อย!)

ในการลบทรัพยากร AWS ต้องทำตามลำดับย้อนกลับเพื่อป้องกัน **Dependency Error** และป้องกันการถูกคิดเงิน:

1. Terminate EC2 ➔ 2. Delete NAT GW ➔ 3. Release Elastic IP ➔ 4. Detach/Delete IGW ➔ 5. Delete VPC

💰 กฎการคิดเงิน (Billing Rules):

  • VPC, Subnets, Route Tables และ Internet Gateway (IGW) = ฟรี ไม่มีค่าบริการ
  • NAT Gateway และ Elastic IP (EIP) = คิดเงินรายชั่วโมง!
  • เงื่อนไขพิเศษ Elastic IP: ถ้าผูกติดกับ EC2 ที่กำลัง Running จะไม่ถูกคิดเงินเพิ่ม แต่ถ้า EC2 ถูก Stopped หรือ EIP Unattached (ปล่อยว่าง) AWS จะคิดเงินค่าจอง IP ทันที!
